# .claude フォルダについて

Claude Code に読ませるための置き場所。用途ごとに 3 つに分けてある。

このファイル自体は Claude Code に自動では読み込まれない、**人間向けの覚え書き**。

---

## skills/ — 手順書

決まった手順を書いておくと、Claude が必要なときに読んで、そのとおりに動く。
**毎回同じことを説明しなくて済む**ようにするための場所。

置き方は、手順書 1 つにつきフォルダを 1 つ作り、その中に `SKILL.md` を置く。

```
.claude/skills/取材音声を文字起こしする/SKILL.md
```

`SKILL.md` の先頭には、次の形式で名前と説明を書く（これが無いと読み込まれない）。

```markdown
---
name: 取材音声を文字起こしする
description: いつこの手順書を使うのか。Claude はこの一文を見て、使うかどうかを判断する。
---

（ここから下に、手順を普通の文章で書く）
```

使うときは、会話の中で `/取材音声を文字起こしする` と打つ。
`description` に当てはまる場面だと Claude が自分で判断して読むこともある。

**向いているもの**: 毎回同じ順番でやる作業。
（例: 新しい取材音声を処理して結果を確認するまでの一連の流れ）

---

## agents/ — 担当者

特定の仕事だけを任せる「担当者」を作れる。
本体の会話とは**別の場所で作業する**ので、長い調べものをさせても会話が散らからない。

置き方は、担当者 1 人につき `.md` ファイルを 1 つ。

```
.claude/agents/ワイン用語チェック.md
```

ファイルの先頭に書くもの:

```markdown
---
name: ワイン用語チェック
description: 何をする担当者か。呼び出すかどうかの判断に使われる。
tools: Read, Grep, Glob
---

（ここから下に、その担当者への指示を書く）
```

`tools` の行は省略できる。省略すると全部の道具が使える。
読むだけの担当者なら、上の例のように読み取り系だけに絞っておくと安全。

**向いているもの**: 範囲が決まっていて、結果だけ受け取れればよい調べもの。

---

## rules/ — 細かいルール

> **注意: このフォルダは Claude Code が自動では読みません。**
> `skills/` と `agents/` は決まった置き場所だが、`rules/` はそうではないので、
> ファイルを置いただけでは効かない。

効かせるには、`CLAUDE.md` から呼び出す（取り込む）。
`CLAUDE.md` に次の 1 行を書くと、そのファイルの中身がその場に読み込まれる。

```markdown
@.claude/rules/ワイン用語の表記.md
```

**分けておく利点**は、`CLAUDE.md` が長くなりすぎないこと。
「ワインの表記ルール」「パティスリーの表記ルール」のように話題ごとにファイルを分け、
`CLAUDE.md` からは 1 行ずつ呼ぶ、という使い方ができる。

**向いているもの**: 分量が増えていく一覧。
（例: フランス語の固有名詞をどうカタカナで書くかの取り決め）

---

※ 空のフォルダは git に保存できないため、各フォルダに `.gitkeep` という空のファイルを置いてある。
中身を入れたら消してかまわない。
